# IPC Contract 审查清单

<!-- 本清单是插件通用基线，项目本地审查规则可覆盖 -->

## 结构完整性

- [ ] `id` 字段存在且符合项目 ID 模式（如 `IPC-{nnn}`）
- [ ] `title` 清晰描述 IPC 通道范围
- [ ] `version` 字段存在且符合语义化版本
- [ ] `status` 字段存在且为有效值

## 消息定义

- [ ] 请求消息结构完整
- [ ] 响应消息结构完整
- [ ] 事件消息定义清晰（如适用）
- [ ] 消息类型定义使用 TypeScript 接口

## 通道规范

- [ ] 通道名称明确
- [ ] 通信方向清晰（前端→后端/后端→前端/双向）
- [ ] 请求和响应示例完整
- [ ] 错误码覆盖常见异常场景

## 序列化规范

- [ ] 数据格式明确（JSON/MessagePack/Protobuf）
- [ ] 类型映射表完整
- [ ] 日期和数字精度有说明
- [ ] 字符编码有说明

## 边界规则

- [ ] 前端职责范围明确
- [ ] 后端职责范围明确
- [ ] 禁止事项有明确说明
- [ ] 前后端边界清晰无歧义

## 错误处理

- [ ] 错误码定义完整
- [ ] 错误消息用户友好
- [ ] 错误恢复方式明确
- [ ] 不暴露内部实现细节

## 性能要求

- [ ] 延迟指标有明确目标
- [ ] 大数据传输策略有说明
- [ ] 并发限制有说明
- [ ] 超时设置有说明

## 安全性

- [ ] 输入验证规则完整
- [ ] 权限控制机制明确
- [ ] 敏感信息处理有说明
- [ ] 防攻击措施有说明

## 版本兼容

- [ ] 向后兼容规则明确
- [ ] 破坏性变更有处理流程
- [ ] 版本迁移有说明
- [ ] 旧版本兼容期有定义

## 追溯性

- [ ] 关联功能特性存在
- [ ] IPC 通道可追溯到业务需求
- [ ] 与 UI 契约关联清晰

## 实现一致性

- [ ] 与实际实现代码一致
- [ ] 文档与实际行为匹配
- [ ] 类型定义与代码类型一致
