# OSS Compliance 审查清单

<!-- 本清单是插件通用基线，项目本地审查规则可覆盖 -->

## 结构完整性

- [ ] `id` 字段存在且符合项目 ID 模式（如 `OSS-{nnn}`）
- [ ] `title` 清晰描述合规范围
- [ ] 适用仓库、包或发布目标明确
- [ ] 关联的发布策略或发布技能已记录

## 许可证策略

- [ ] 项目许可证明确
- [ ] 允许、需审查和禁止的依赖许可证范围明确
- [ ] 许可证策略与发布目标一致
- [ ] 许可证异常有审批和到期机制

## 依赖审查

- [ ] 第三方依赖清单完整
- [ ] 每个依赖的许可证和用途已记录
- [ ] 高风险依赖有处理结论
- [ ] 依赖审计命令可执行

## 发布文件

- [ ] `LICENSE` 存在且内容正确
- [ ] `NOTICE` 是否需要已判断
- [ ] README、CHANGELOG、SECURITY、CONTRIBUTING 等标准文件齐备
- [ ] 包元数据中的 license/repository/homepage 字段正确

## 发布排除

- [ ] 不会发布父工程私有制品或内部规划文档
- [ ] 不包含本机绝对路径
- [ ] 不包含 token、密钥、凭据或内部 URL
- [ ] 不包含未授权第三方素材

## 安全与披露

- [ ] 安全报告入口明确
- [ ] 漏洞披露流程明确
- [ ] 敏感信息扫描流程已定义
- [ ] 阻塞级安全问题不会进入发布

## 追溯性

- [ ] 关联发布策略存在
- [ ] 关联发布技能存在（如适用）
- [ ] 合规结论可追溯到发布治理需求
