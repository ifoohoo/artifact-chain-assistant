# Scenario 审查清单

<!-- 本清单是插件通用基线，项目本地审查规则可覆盖 -->
<!-- 场景剧本是结构化的发现级场景：先于/驱动 PRD 与功能特性，功能是场景的派生物；
     表达形式是结构化的（字段块 + Given/When/Then） -->

## 结构完整性

- [ ] `id` 字段存在且符合项目 ID 模式（如 `S-{nn}`）
- [ ] `title` 字段存在且描述场景本质
- [ ] `status` 字段存在且为有效值
- [ ] 节点标题符合解析锚点形式：主场景 H2、变体 H3，编号匹配 `^S-\d+[a-z]?$`，冒号形式与项目模板一致

## 字段块完整性

- [ ] 每个节点都有 `**关联功能**` 与 `**关联决策**`（机器锚点、必需）
- [ ] 每个节点都有 `**场景代码**` 稳定 slug（推荐）
- [ ] 项目扩展字段（如入口编号）符合项目模板

## Given/When/Then 可验证性

- [ ] Given 是可构造的具体前置状态，不是泛泛背景描述
- [ ] When 是编号步骤的具体动作
- [ ] Then 是可观察、可验证的结果（输出、退出码、状态、记录），无口号、无模糊词

## 变体覆盖

- [ ] 关键分支、边界、异常有变体节点覆盖
- [ ] 变体复用主场景语境、只写差异，且同样声明字段块

## 追溯一致

- [ ] `关联功能`/`关联决策` 只引用制品图中已存在的 ID，无编造关联（引用不存在的 ID 是错误）
- [ ] 关联功能存在时，功能制品 frontmatter 的 `scenarios` 字段回列本场景（双向一致）
- [ ] 尚无功能制品时，`关联功能` 行按项目模板约定省略或标注（发现级暂态，记 info/warning，不判 fail）
- [ ] `ORPHAN_SCENARIO` warning（无功能关联、不阻断）在发现级场景下属预期，可按 warning 接受
- [ ] 场景→决策边只对 `D-XXX-数字` 形式成边；`ADR-\d{4}` 类编号只做文档级追溯，未当作图边

## 行文

- [ ] 无空洞词、排队连接词、三连排比、四字堆砌等 AI 腔（按密度原则判断）
- [ ] Then 写可观察事实，不写口号；数字只在真实时写
- [ ] 正文无本机绝对路径（如 `<用户主目录>/xxx`、`~/xxx`），路径为项目相对形式或占位符
