# Release Policy 审查清单

<!-- 本清单是插件通用基线，项目本地审查规则可覆盖 -->

## 结构完整性

- [ ] `id` 字段存在且符合项目 ID 模式（如 `RP-{nnn}`）
- [ ] `title` 清晰描述发布策略范围
- [ ] `version` 已指定
- [ ] 适用范围明确

## 版本策略质量

- [ ] 主/次/补丁版本递增规则清晰
- [ ] 预发布标签使用规则已定义
- [ ] 版本策略与项目实际发布流程一致
- [ ] 破坏性变更有明确识别标准

## 发布流程质量

- [ ] 发布步骤可执行
- [ ] 构建与验证命令完整
- [ ] 发布后确认清单完整
- [ ] 准备阶段检查项覆盖关键质量门禁

## 分支与节奏

- [ ] 分支策略与团队实际工作流匹配
- [ ] 发布节奏合理（不过频也不过疏）
- [ ] 紧急发布流程有明确触发条件
- [ ] 分支保护规则已定义

## 变更日志规范

- [ ] 变更日志格式已指定
- [ ] 必须包含的变更类别已定义
- [ ] 变更日志更新是发布流程的门禁步骤

## 合规要求

- [ ] 许可证检查流程已定义
- [ ] 安全扫描流程已定义（如适用）
- [ ] 第三方依赖审计已定义（如适用）
- [ ] 合规要求与项目类型匹配

## 回滚策略

- [ ] 回滚触发条件明确
- [ ] 回滚步骤可执行
- [ ] 回滚通知机制已定义
- [ ] 回滚影响已评估

## 追溯性

- [ ] 关联功能特性存在
- [ ] 关联决策存在
- [ ] 发布策略可追溯到治理需求
