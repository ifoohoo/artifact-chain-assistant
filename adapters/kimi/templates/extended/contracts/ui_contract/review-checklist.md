# UI Contract 审查清单

<!-- 本清单是插件通用基线，项目本地审查规则可覆盖 -->

## 结构完整性

- [ ] `id` 字段存在且符合项目 ID 模式（如 `UI-{nnn}`）
- [ ] `title` 清晰描述 UI 流程范围
- [ ] `version` 字段存在且符合语义化版本
- [ ] `status` 字段存在且为有效值

## 用户流程

- [ ] 主流程步骤清晰完整
- [ ] 分支流程有明确条件说明
- [ ] 流程起始和结束状态明确
- [ ] 用户操作和系统响应对应关系清晰

## 状态管理

- [ ] 所有状态已列出
- [ ] 状态转换条件明确
- [ ] 无死循环或不可达状态
- [ ] 错误状态有恢复路径

## 交互设计

- [ ] 表单元素类型和验证规则完整
- [ ] 按钮行为和禁用条件明确
- [ ] 快捷键定义清晰（如适用）
- [ ] 加载状态有明确反馈

## 错误处理

- [ ] 错误类型覆盖完整（网络、验证、权限、服务器）
- [ ] 错误提示用户友好
- [ ] 错误恢复方式明确
- [ ] 错误展示方式符合设计规范

## 可访问性

- [ ] ARIA 标签完整
- [ ] 键盘导航支持
- [ ] 颜色对比度符合标准
- [ ] 屏幕阅读器兼容

## 响应式设计

- [ ] 断点定义清晰
- [ ] 各断点布局调整明确
- [ ] 元素变化有说明
- [ ] 移动端交互适配

## 性能要求

- [ ] 性能指标有明确目标
- [ ] 测量方式有说明
- [ ] 关键路径有优化策略

## 追溯性

- [ ] 关联功能特性存在
- [ ] UI 流程可追溯到业务需求
- [ ] 与 API 契约关联清晰

## 实现一致性

- [ ] 与实际实现代码一致
- [ ] 文档与实际行为匹配
- [ ] 设计稿与文档描述一致
