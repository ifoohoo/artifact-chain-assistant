# Batch Job Contract 审查清单

<!-- 本清单是插件通用基线，项目本地审查规则可覆盖 -->

## 结构完整性

- [ ] `id` 字段存在且符合项目 ID 模式（如 `BATCH-{nnn}`）
- [ ] `title` 清晰描述批处理作业范围
- [ ] `version` 字段存在且符合语义化版本
- [ ] `status` 字段存在且为有效值
- [ ] `schedule` 字段存在且为有效 cron 表达式

## 输入定义

- [ ] 所有数据源已列出
- [ ] 数据源类型明确（数据库 / 文件 / API / 消息队列）
- [ ] 输入参数完整且类型明确
- [ ] 输入格式示例正确

## 输出定义

- [ ] 所有输出目标已列出
- [ ] 输出目标类型明确
- [ ] 输出参数完整且类型明确
- [ ] 输出格式示例正确

## 处理逻辑

- [ ] 主流程步骤清晰
- [ ] 分片策略已定义（方式、大小、并行度）
- [ ] 过滤条件已列出
- [ ] 边界情况处理已说明

## 幂等性

- [ ] 幂等策略已定义
- [ ] 唯一键组成字段明确
- [ ] 冲突处理策略已说明
- [ ] 重复执行行为已定义

## 错误处理

- [ ] 错误分类已定义（数据 / 系统 / 业务）
- [ ] 每类错误的处理策略已说明
- [ ] 错误记录方式已定义
- [ ] 单条失败处理策略已说明
- [ ] 批量失败处理策略已说明
- [ ] 作业失败处理策略已说明

## 监控与告警

- [ ] 关键监控指标已定义（处理量、成功数、失败数、时长）
- [ ] 告警规则已定义

- [ ] 监控阈值合理

## 性能要求

- [ ] 预期数据量已评估

- [ ] 资源限制已说明

## 回滚策略

- [ ] 回滚条件已定义

- [ ] 数据一致性保证已说明

## 追溯性

- [ ] 关联功能特性存在
- [ ] 批处理作业可追溯到业务需求
- [ ] 版本变更可追溯
- [ ] 关联设计文档存在

## 实现一致性

- [ ] 与实现代码一致
