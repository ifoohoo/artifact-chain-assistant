# 条件检查

识别到相应风险时使用，检查本次规格决定所需的事实。

## 前置依赖与阶段

验收是否依赖发布后、候选形成后或上游开放后才存在的材料？将检查放回正确阶段，并保留尚未发生的结果。

最早阻断门是否发生在所需生成步骤之前？核对项目提供的依赖和既有编排责任，调整生成与检查顺序，避免两处重复生成相同内容。

## 输入版本与证据

恢复时核对当前目标、工具、源码和生成物。实际输入发生变化时，复核受影响观察；原始输入未变的有效结论可沿用。缺少原始输出或无法定位版本时，说明对应证据缺口。

## 入口与交接

选定入口能否接受本次用例、目标树和任务类型？读取公共合同及调用方，核对样本限制、隐含全量前置与合同版本。决定性疑点通过现有入口的最小观察澄清；改变采用机制时，修订同一 SPEC 的受影响决定。

连续停在入口研究而无新事实时，明确缺的是合同、材料、项目定义还是执行能力。交接保留本次任务、必要合同、已证伪路径与下一动作。

## 读集与产品终点

按[执行编排与分层读取](execution-contract.md#3-规定读取时机不扩大上下文)展开实际必读引用，找出无关整份材料与混入的历史。目录分层和文件变短不等于当前必要读集已经减少。

按[启动提示与任务交接](execution-contract.md#21-启动提示与任务交接)核对产品目标、首项工作和完成条件。以真实用户起点判断产品终点，分别记录语义审阅、工程检查和实际宿主行为的覆盖范围。中间步骤成功后，仍核对本次要求的产品结果。
